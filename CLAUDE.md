# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this app is

A diagnostic Android app for a BYD DiLink car head unit. **The final result this project delivers: long-pressing the SWC (steering-wheel control) Voice Assistant button on the BYD triggers Siri on the iPhone over Bluetooth** — by sending HFP `AT+BVRA=1` to the Bluetooth-connected iPhone. The long-press event is natively unused (BYD's assistant runs on *short* press, a different event), so no gating or pass-through is needed: with no phone connected the press is simply a silent no-op. The app was built to *answer three unknowns empirically* (see README.md). Field-testing on the unit has confirmed the first two: DiLink's BT stack is Android's, and the reflection call works — the test button activates Siri on the iPhone. The SWC voice button is kernel event `BTN_TL2`, which DiLink's vendor key layout delivers to the AccessibilityService as keycode **312** (confirmed via discovery mode; not AOSP's generic 104/BUTTON_L2) — the default trigger keycode. DiLink has no Accessibility settings screen, so the service is enabled by writing secure settings directly (needs `WRITE_SECURE_SETTINGS` granted via adb; see README). Failure messages are the product — every error path returns a human-readable diagnostic string shown as a toast/status, not just a log line. Preserve that property when changing code.

## Build

- **After every code change: bump `versionCode`/`versionName` in `app/build.gradle` and build both variants (`./gradlew assembleDebug assembleRelease`) before finishing.** The deliverable the user installs is `app/build/outputs/apk/release/siri-trigger-<versionName>.apk` (the version is part of the filename automatically).
- `./gradlew assembleRelease` for the production APK (signed with the checked-in personal-use `release.keystore`; passwords are in `app/build.gradle`), `./gradlew assembleDebug` for testing. Both output `siri-trigger-<versionName>.apk` under `app/build/outputs/apk/<variant>/`. AGP 8.x with a Gradle 8.13 wrapper (requires JDK 17–21 to run; Android Studio's embedded JBR works: `JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"`).
- Java 8 source/target, compileSdk 33, minSdk 26. Plain Java, no Kotlin, no dependencies, no tests. `applicationId` is `com.ptuchik.siritrigger` (hyphens are invalid in Android application IDs); the Java `namespace` is `com.ptuchik.siri` — they intentionally differ.
- Install the APK on the head unit via ADB or file-manager sideload.

## Architecture

Three classes in `app/src/main/java/com/ptuchik/siri/`, two entry points:

- **`HfpSiriTrigger`** — singleton (`HfpSiriTrigger.get(ctx)`) that binds the *hidden* HFP-client profile (`BluetoothProfile.HEADSET_CLIENT` = 16, hardcoded because the constant is not in the SDK) and invokes `startVoiceRecognition(BluetoothDevice)` **via reflection**. Do not replace the reflection/`Object` handling with SDK types — the class (`BluetoothHeadsetClient`) is hidden and won't compile against the public SDK. Binding happens once at first `get()` with throttled automatic rebind via `ensureBound()`; `lastStatus` records the outcome for the UI. Phone detection is two-layered: the proxy's `getConnectedDevices()` (needs the runtime `BLUETOOTH_CONNECT` permission on Android 12+ — reinstalls reset it; MainActivity re-requests it on launch), plus an ACL connect/disconnect tracker fed by `ReviveReceiver` that also supplies a fallback `BluetoothDevice` for the trigger when the proxy list is empty. **Siri answering over A2DP (media channel) is accepted behavior — do not "fix" it.** An SCO-first variant (bring the telephony link up before `AT+BVRA` via `setAudioRouteAllowed`/`connectAudio`/`getAudioState` polling) was implemented in v1.0.4 and deliberately reverted: it added up to 600 ms latency and was unstable on this unit.
- **`KeyCatcherService`** — AccessibilityService with `flagRequestFilterKeyEvents` (config in `res/xml/keycatcher_config.xml`). Two modes: *discovery* (toast/log every keycode, never consume) and *trigger* (key DOWN of the configured keycode → `HfpSiriTrigger` immediately, all events of that key consumed; no phone-connected gating — a failed attempt is a silent no-op in live mode). DiLink has a "Disable Self-Start" app list that blocks background process starts, and every app is blocked by default (its toggle in the list is ON = self-start disabled). Siri Trigger's toggle must be turned OFF there — otherwise nothing auto-starts after reboot (no `BOOT_COMPLETED`, no boot-time accessibility bind) and the app is dead until launched manually. Additionally, DiLink sometimes restores the accessibility setting at boot without binding the service ("enabled" but dead — no key events). `KeyCatcherToggle.kick()` fixes this by removing/re-adding the component in `enabled_accessibility_services` (needs `WRITE_SECURE_SETTINGS`), invoked from `ReviveReceiver` (BOOT_COMPLETED and Bluetooth ACL_CONNECTED — i.e. when the iPhone pairs at ignition; it waits 3 s and only kicks if the service is still unbound, never touching a healthy one), MainActivity launch, and the enable button. `KeyCatcherService.isRunning()` (static flag set in `onServiceConnected`/cleared in `onUnbind`) is the truth for whether the service is actually bound — never trust the setting string alone.
- **`MainActivity`** — manual test button (fires the HFP trigger directly, bypassing the key path), shortcut to Accessibility settings, and settings editor.

The two components communicate only through SharedPreferences: file `"siri"` (`KeyCatcherService.PREFS`), keys `debug_mode` (bool, default **false** = silent "live mode": no toasts, no logs, discovery inert; `HfpSiriTrigger.setDebugLogging` mirrors it into a static flag), `discovery_mode` (bool) and `trigger_keycode` (int, default 312, the BYD SWC voice button). MainActivity writes, the service reads on every key event.

## Testing / debugging

There is no emulator path that means anything — behavior must be verified on the head unit. Follow the ordered test procedure in README.md (on-screen HFP test first, then keycode discovery, then arming the trigger). Logs: `adb logcat -s HfpSiriTrigger KeyCatcher`. If hidden-API enforcement blocks reflection: `adb shell settings put global hidden_api_policy 1`.
